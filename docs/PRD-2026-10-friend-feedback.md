# PRD: 친구 피드백 반영 (분류 정리 · 인원 미정 · 프로필 소개)

- 작성일: 2026-10-28
- 근거: 송영진 님 카카오톡 피드백(2026-10-25, 스크린샷 4장)
- 대상: https://mahamuder.web.app (게임 목록, 게임 카드·상세, 마이페이지)
- 데이터 현황(2026-10-28, Firestore 공개 REST 기준): 게임 667개, 인원 정보 없음 122개, 최대 인원 10명 이상 21개

## 1. 배경

사이트를 처음 본 친구(머더미스터리 실물 패키지를 많이 가진 사용자)가 세 가지를 우선순위로 짚었습니다.

> 일단 3개정도? 1.카테고리 2.인원미정 3.개인 프로필 및 소개

공통된 이유는 두 가지입니다.

1. **스포일러**: 머더미스터리는 "이세계", "판타지", "미래" 같은 배경 장르만 알아도 반전이 드러날 수 있다.
2. **혼란**: 게임이 많아서(667개) 분류가 겹치거나 미정 데이터가 섞이면 목록이 금방 지저분해진다.

## 2. 목표와 비목표

**목표**
- 게임 분류를 겹치지 않는 3개로 줄이고, 스포일러가 될 수 있는 배경 태그를 화면에서 없앤다.
- 인원 필터를 골랐을 때 인원 미정 게임이 섞이지 않게 한다.
- 마이페이지의 선호 장르를 자유 입력으로 바꾸고, 선호 플레이 시간에 "~1시간"을 넣는다.

**비목표**
- 분류 아래 세부 그룹(이세계·판타지 등): 친구가 처음 제안했다가 스포일러 때문에 스스로 철회함.
- 게임 데이터 자체의 인원 정보 채우기(122개): 별도 작업(CSV 보강, `update-mm-games`).

## 3. 현재 상태와 문제

| 영역 | 지금 | 문제 |
|---|---|---|
| 장르 필터(`GamesPage.tsx`) | `allGenres()`로 모든 태그를 드롭다운에 나열: 머더미스터리 418 · 추리·탐정 150 · 미스터리·추리 97 · 소셜 디덕션 16 · 추리 2 · 판타지 1 · 이세계 1 · 미래 1 | "추리", "추리·탐정", "미스터리·추리"가 사실상 같은 뜻. 배경 태그는 스포일러 |
| 카드·상세 태그 | `genres`를 그대로 칩으로 표시 | 위와 같음 |
| 인원 필터 | `(g.minPlayers \|\| 0) <= size && size <= (g.maxPlayers \|\| g.minPlayers \|\| 99)` | 인원이 비면 0~99로 계산돼 3~10명 **모든 선택지에 122개가 다 나옴**. "10명이서 + 구비 전체"에서도 미정 게임이 줄줄이 나옴 |
| 인원 선택지 | 3~10명 | 10명 이상 게임(21개, 주로 소셜 디덕션)을 고를 방법이 없음 |
| 선호 장르(`MyPage.tsx`) | 게임 태그 칩을 고름. 친구 목록 표와 "추천 게임" 점수에 쓰임 | 태그가 스포일러라 고르는 것 자체가 부담 |
| 선호 플레이 시간 | `~2시간 / 2~4시간 / 4시간 이상 / 상관없음` | 소셜 디덕션은 1시간 안쪽 게임이 많은데 선택지가 없음 |

## 4. 요구 사항

### P1. 장르 → "분류" 3개로 정리

**R1-1. 분류 정의** (용어는 "카테고리" 대신 "분류")

| 분류 | 괄호 설명 | 한 줄 소개(안내 문구) |
|---|---|---|
| 머더미스터리 | 역할극 | 각자 맡은 인물을 연기하며 범인을 찾는다 |
| 추리 | 협력 추리 | 모두 함께 단서를 모아 사건을 푼다 |
| 소셜 디덕션 | 마피아류 | 숨은 정체를 두고 서로 속이고 밝혀낸다 |

- 필터 드롭다운: `분류 전체 / 머더미스터리(역할극) / 추리(협력 추리) / 소셜 디덕션(마피아류)`.
- 소개 문구는 필터 옆 `?` 버튼(툴팁 또는 작은 모달)로 보여 준다. 따로 페이지를 만들지는 않는다(필요하면 나중에 FAQ `src/data/site.ts`에 추가).

**R1-2. 데이터**: 게임에 단일 값 `category: "murder" | "deduction" | "social"`을 추가한다.
- `types.ts`의 `Game`, `firestore.rules`의 `editableFields()`와 타입 검사(세 값 중 하나), `GameForm`(태그 입력칸 → 분류 라디오), `csvGames.ts`(장르 열 → 분류 변환)를 함께 고친다.
- 기존 게임은 1회 이전 스크립트로 채운다. 규칙(위에서부터 먼저 맞는 것):
  1. 태그에 `소셜 디덕션` → social (16개)
  2. 태그에 `머더미스터리` → murder (420개, `머더미스터리+소셜 디덕션` 1개는 1번에서 처리)
  3. 태그에 `추리`/`추리·탐정`/`미스터리·추리` → deduction (약 219개)
  4. 나머지(태그 없음 11개, `이세계+판타지` 1개) → 비워 두고 목록에서 "분류 없음"으로 직접 정리
- 이전 순서: hosting 배포(새 화면이 `category`를 읽고 씀) → 규칙 배포 → 이전 스크립트. 쓰기 권한은 회원 로그인이 필요하므로 데모 모드에서 먼저 검증한 뒤 실제 사이트에서는 사용자가 직접 실행하거나 앱 안의 관리 버튼으로 한다.

**R1-3. 배경 태그 숨김**: 카드·상세·검색어 매칭에서 `genres`를 더 이상 보여 주거나 쓰지 않는다. 카드에는 분류 칩 하나만 표시한다. `genres` 필드는 데이터에 남겨 두되(되돌리기용) 화면에서는 읽지 않는다.

**R1-4. SEO**: `seo/plugin.ts`·`lib/seo.ts`에서 `genres`를 쓰는 곳(JSON-LD `genre` 등)을 분류 이름으로 바꾼다. 배경 태그가 정적 HTML·llms.txt에 남지 않게 한다.

**완료 기준**: 드롭다운에 분류 3개만 보이고, 어떤 화면·정적 페이지에도 이세계·판타지·미래 같은 태그가 나오지 않는다.

### P2. 인원 미정 게임 정리

**R2-1. 필터에서 제외**: 인원을 하나라도 고르면 `minPlayers`가 없는 게임은 결과에서 뺀다. "인원 전체"일 때만 보인다.

**R2-2. 미정 선택지**: 인원 드롭다운 맨 아래에 `인원 미정`을 두어 그 122개만 따로 볼 수 있게 한다(데이터 정리용).

**R2-3. 10명 이상**: `10명 이상` 선택지를 추가한다(`maxPlayers >= 10`). 기존 "10명이서"는 유지한다.

**R2-4. 카드 표시**: 인원이 없으면 카드의 "인원" 줄에 눈에 띄는 회색 배지 `인원 미정`을 보여 준다(기존 `players()` 문구를 배지 스타일로). 가격 미정·시간 미정도 같은 스타일로 맞추면 일관됨(선택).

**완료 기준**: "10명이서 + 구비 전체"에 인원 미정 게임이 0개. "인원 미정"을 고르면 122개(데이터가 바뀌면 그 수)가 나온다.

### P3. 개인 프로필 및 소개

**R3-1. 선호 장르 → 자유 입력**: 칩 목록을 없애고 "한마디"와 같은 형태의 짧은 입력칸 `좋아하는 스타일`(예: "반전 많은 거, 범인 역할 좋아해요", 최대 60자)을 둔다. 새 필드 `prefNote`(문자열)를 `Profile`·두 백엔드·`firestore.rules`에 추가한다.
- 기존 `prefGenres`는 화면에서 읽지 않는다(각자 문서라 일괄 삭제는 하지 않음).
- 친구 목록 표의 "선호 장르" 열은 `prefNote`로 바꾼다.

**R3-2. 추천 점수**: `Recommend`가 `prefGenres` 대신 내가 선호 표시(`liked`)하거나 높게 평가한(평점 4 이상) 게임의 **분류**와 같은 분류에 가중치를 준다.

**R3-3. 선호 플레이 시간 선택지**: `~1시간 / 1~2시간 / 2~4시간 / 4시간 이상 / 상관없음`.
- 예전 값 `~2시간`이 저장된 사람은 `1~2시간`으로 보이게 화면에서 바꿔 읽는다(다음에 고를 때 새 값으로 저장).

**완료 기준**: 마이페이지에 장르 칩이 없고, 자유 입력이 저장·표시된다. "~1시간"을 고를 수 있다.

## 5. 우선순위와 순서

| 순서 | 항목 | 크기 | 메모 |
|---|---|---|---|
| 1 | P2 인원 미정 (R2-1~R2-4) | 작음 | `GamesPage.tsx` 필터 한 줄 + 선택지 + CSS. 데이터 변경 없음, 바로 배포 가능 |
| 2 | P3 프로필 (R3-1~R3-3) | 중간 | 필드 1개 추가(인터페이스·두 백엔드·규칙) |
| 3 | P1 분류 (R1-1~R1-4) | 큼 | 데이터 이전·규칙·폼·CSV·SEO까지 걸침 |

친구의 우선순위는 분류가 1번이지만, 인원 미정은 영향 대비 작업이 가장 작아 먼저 내보내는 것을 권장합니다.

## 6. 검증

- `npm run typecheck`
- `npm run dev:demo`에서 localStorage `mm_games`에 분류별·인원 미정·10명 이상 게임을 넣어 필터 조합 확인
- 이전 스크립트는 공개 REST로 읽은 실제 목록에 대해 먼저 "몇 개가 어떤 분류로 가는지"만 출력하는 건식 실행을 한다
- 규칙: `firebase deploy --only firestore:rules --dry-run`, 기존 게임 문서가 새 검사를 통과하는지 REST로 확인
- 빌드 로그에 `게임 N개를 ... 만들어요`, 정적 페이지에 배경 태그가 없는지 `grep`

## 7. 열린 질문 (피드백에서 나왔지만 범위 밖)

1. **사용자층 안내**: "이용자가 누구지? 교회 청년들? 모든 시민?"이라는 질문이 먼저 나왔습니다. 첫 화면에 "교회 청년 모임 친구들끼리 쓰는 초대제 사이트"라는 한 줄을 넣을지.
2. **보유 게임의 의미**: 보유 게임 목록을 보고 "교회 어디 장소에 따로 보관해야 하나?"라고 물었습니다. 보유 = 각자 집에 두고 모임 때 빌려 주는 것이라는 설명을 `/library` 상단에 넣을지, 보관 장소 필드가 필요한지.
3. **분류 소개 위치**: 툴팁으로 충분한지, FAQ나 별도 안내 항목으로 키울지.
