# 머더미스터리 게임 CSV 업데이트

저장소 루트의 `murder_mystery_games.csv`(BOM 있는 UTF-8, CRLF)에 세 사이트의 새 게임을 덧붙인다. 기존 행은 고치지 않는다.

일은 **스크립트가 모으고, Claude가 판단하고, 스크립트가 쓰는** 순서다. 사이트 읽기·중복 검사·CSV 형식은 스크립트가 정확하게 하고, "이게 머더미스터리 게임인가", "홍보 문구에서 게임 이름이 뭔가", "같은 게임의 재판매인가" 같은 판단만 Claude가 한다. 스크립트는 모두 `scripts/`에 있고 Node 18+ 표준 기능만 쓴다(설치할 것 없음).

## 0. 준비

- 네트워크가 필요하므로 이 저장소에서는 **샌드박스 밖**에서 실행한다(CLAUDE.md 참고). `python`은 없으니 보조 스크립트도 `node`로.
- 작업 폴더는 스크래치패드(없으면 OS 임시 폴더)의 `mm-update/`로 한다. 저장소 안에 중간 파일을 만들지 않는다.
- 아래에서 `S`는 이 스킬의 `scripts` 폴더, `W`는 작업 폴더, CSV는 저장소 루트의 `murder_mystery_games.csv`.

## 1. 후보 모으기 (1~2분)

```bash
node S/collect.mjs --csv murder_mystery_games.csv --out W
```

사용자가 특정 사이트만 원하면 `--only tumblbug`(쉼표로 여러 개)처럼 줄인다. 결과:
- `W/candidates.json`: 전체 자료
- `W/candidates.md`: 사이트별 요약. 각 후보에 `new`(CSV에서 못 찾음) / `maybe ≈ 기존이름`(이름이 겹침, 확인 필요)이 붙고, CSV에 이미 있는 것(`known`)은 빠진다.

각 사이트에서 무엇을 읽는지:
- **보드라이프**: 여러 검색어("머더 미스터리", "추리", "살인", "mystery" 등)의 보드게임 검색 결과 중 CSV의 보드라이프 주소에 없는 게임과 그 상세(인원·시간·연령·난이도·언어의존도·평점·확장 여부). 검색어가 넓어서 **관계없는 게임이 꽤 섞인다**(예: "추리"로 "센추리"가 잡힘).
- **텀블벅**: "머더미스터리"·"머더 미스터리"·"머미" 검색 결과 중 보드게임·TRPG 분류 프로젝트. 제목이 홍보 문구라서 게임 이름은 보통 `<…>`, `「…」`, `[…]` 안에 있다.
- **머미나우**: `머더미스터리 > 보드게임` 분류의 상품과 상세(인원·소요시간·작가·퍼블리셔·출시일). 개인 운영·플랫폼(온라인)·테마공연 분류는 실물 게임이 아니라서 읽지 않는다.

## 2. 초안 만들기 (20초쯤)

```bash
node S/draft.mjs --in W/candidates.json --out W/drafts.json
```

`new`·`maybe` 후보를 CSV 행 초안으로 바꾼다. 텀블벅과 머미나우에 같은 게임이 있으면 한 행으로 합치고, 텀블벅 한 프로젝트에 여러 게임(`<A><B>`)이 있으면 게임마다 한 행, 실패·취소·공개 전 프로젝트와 머미나우에서 `온라인` 표시가 붙은 상품은 뺀다. 텀블벅 가격은 게임 이름이 들어간 선물(없으면 후원자가 가장 많은 1만 원 이상 선물)의 펀딩가다. 초안마다 `_key`(`bl:<보드라이프id>`, `mn:<상품번호>`, `tb:<permalink>[#n]`), 판단에 쓸 `_note`, 이름이 같은 초안이 먼저 있으면 `_sameName`(재펀딩·이중 등록 표시)이 있다.

## 3. 검토 (Claude가 하는 일)

처음 실행하면 초안이 500개 넘게 나오고(그중 150개쯤은 이름이 없다), 다음부터는 새로 나온 것만이라 수십 개다. 많을 때는 이 순서가 빠르다.

1. **이름 없는 초안·묶음부터**: `node S/show.mjs W/drafts.json --noname --full --to 40`. `_note`에 선물 목록이 있어서 대부분 여기서 이름이 나온다. 그래도 모르면 `node S/detail.mjs tumblbug <permalink...>`(여러 개 한 번에)로 소개글을 본다.
2. **사이트별 나머지**: `node S/show.mjs W/drafts.json --only mn: --from 0 --to 80`처럼 80개씩. 출력이 길면 범위를 줄인다.
3. 결정은 `W/review.json`에 쌓는다. 결정이 많으면 JSON을 직접 쓰기보다, 결정 목록을 담은 작은 node 스크립트(`W/build-review.mjs`)가 review.json을 만들게 하면 고치기 쉽다. 그 스크립트에서 `scripts/lib.mjs`를 가져오려면 Windows에서는 `pathToFileURL(경로).href`로 import한다.

```json
{
  "drop": ["bl:8223", "tb:mysteryparty"],
  "edit": {
    "tb:941_81_1_always": { "게임명(한글)": "외계인이 내려와 하는 말", "최소인원": "5", "최대인원": "5" },
    "bl:17149": { "장르": "추리·탐정" }
  },
  "add": []
}
```

`drop`은 `_key`를 그대로 적는다. 끝에 `*`를 붙이면 앞부분이 같은 것을 모두 뺀다(`"tb:mysteryparty*"`). `*`는 신중히: `tb:mysterygames*`는 다른 게임인 `mysterygames10`~`20`까지 빼 버린다.

`add` 행은 `_key` 없이 CSV 머리글로 쓴다. 묶음을 나눌 때는 원래 초안의 출판사·출시연도·이미지URL·출처URL·장르를 그대로 옮기고, 이름·인원·시간·가격만 게임별로 바꾼다(가격은 그 게임의 단품 선물이 없으면 비운다). 같은 출처URL을 여러 행이 나눠 써도 된다.

**무엇을 넣고 뺄지** — 이 CSV는 친구들이 *모여서 실물로 함께할* 추리·미스터리 보드게임을 고르는 데 쓴다(사이트 "머더미스터리 클럽"의 게임 목록 원본). 그래서:
- 넣는다: 머더미스터리(역할을 나눠 범인을 찾는 시나리오 게임), 추리·탐정 보드게임, 미스터리 테마의 협력 추리, 소셜 디덕션 중 살인·사건이 주제인 것. 확장판도 넣는다(`확장여부: 확장`). 인쇄해서 쓰는 PDF 판이 실물판과 함께 나오면 실물판으로 한 행.
- 뺀다: 이름에 "추리·미스터리·살인"이 들어갔을 뿐인 관계없는 게임(센추리, 일반 전략·가족 게임), 사건 추리가 중심이 아닌 방탈출 키트, 굿즈·책·소설·게임북·OST·강의·TRPG 룰북, 온라인 전용·앱·PDF만 있는 것, "이용권/소장권/티켓" 상품, 일회성 공연·이벤트, 디지털 게임.
- **온라인 형식은 꼭 걸러 낸다**(사용자가 원치 않음). 텀블벅은 표시가 없으니 소개를 본다: 웹 "룸"·플랫폼에서 하는 것(랜덤지지/Random.GG, 리얼월드 온라인 등), "인터넷이 가능한 컴퓨터만 있으면", 코코포리아·디스코드로만 하는 것, "온라인 플레이 세트(실물 없음)"만 있는 것은 뺀다. 실물 키트가 있고 온라인은 덤(코코포리아 룸파일 추가, PDF 추가 선물, "온라인 크라임씬의 오프라인 재탄생", QR로 폰을 쓰지만 모여서 하는 것)이면 넣는다. 매장(카페)에서만 할 수 있는 게임은 온라인은 아니지만 보고 때 따로 알린다.
- 확신이 없으면 넣지 말고 마지막 보고에 "보류"로 적는다. 잘못 들어간 행은 사용자가 찾기 어렵지만, 보류 목록은 바로 판단할 수 있다.

**중복 판단** — `maybe ≈ 기존이름`은 대부분 시리즈의 다른 편이거나 재판매다. `new`라도 CSV에 표기만 다르게 있을 수 있다(페성/폐성, 종/종소리, 기묘한/기상천외, 시리즈 이름이 앞에 붙은 경우). 짧거나 흔한 이름이면 `grep`으로 CSV를 한 번 찾아본다. `_sameName`이 붙은 초안은 앞의 초안과 같은 이름이므로 하나만 남긴다.
- 같은 게임의 재펀딩·재판(예: `<미스터리 파티>` 여러 차례 펀딩, "2쇄", "재판매", "팬콜", "앵콜")이면 뺀다. 이미 CSV에 있는 게임이면 전부, 없으면 가장 최근 하나만 남긴다.
- 시리즈의 다른 편(예: `미스터리 로얄 case:01` vs `case:02`)이면 별개의 게임이므로 넣고, 이름을 편 이름까지 분명히 적는다.
- 보드라이프 후보와 텀블벅·머미나우 후보가 같은 게임이면 보드라이프 행을 남기고 다른 쪽을 뺀다(보드라이프 자료가 더 풍부하다). 출처URL에 텀블벅·머미나우 주소를 공백으로 이어 붙여도 된다.

**이름 정하기** — `게임명(한글)`은 상품명이 아니라 게임 이름이다. "7인 머더미스터리", "2종", "by 창작자", 홍보 수식어를 걷어낸다. 이름 없는 초안(`(이름 없음)`)은 `_note`의 제목·소개에서 정하고, 그래도 모르겠으면 `node S/detail.mjs tumblbug <permalink>`로 소개글과 선물 목록을 보고 정한다. 묶음 프로젝트("2종 by 리라이트")는 선물 목록에서 게임 이름을 찾아 `add`로 한 행씩 넣고 원래 초안은 `drop`한다.

**값 채우기** — 모르는 값은 지어내지 말고 비워 둔다(연령·출판사·디자이너는 기존 행처럼 `-`). 텀블벅 초안의 인원·시간은 제목·소개에 있으면 채운다. `장르`는 아래 넷 중에서 1~3개를 `" / "`로 잇는다(기존 CSV와 사이트 필터가 이 값을 쓴다):
- `머더미스터리`: 각자 캐릭터를 맡아 대화로 범인을 찾는 시나리오형(대부분의 텀블벅·머미나우 게임)
- `추리·탐정`: 플레이어가 탐정이 되어 단서를 풀어 가는 게임(셜록 홈즈 사건집, 크라임씬 류)
- `미스터리·추리`: 미스터리 분위기의 일반 보드게임
- `소셜 디덕션`: 숨은 역할을 맞히는 게임(디셉션 등). 다른 장르와 함께 붙인다.

## 4. 미리보기 → 쓰기

```bash
node S/append.mjs W/drafts.json --review W/review.json --csv murder_mystery_games.csv --dry-run
```

형식 문제(이름 없음, 숫자 아닌 인원, 목록에 없는 장르 등)가 하나라도 있으면 아무것도 쓰지 않고 목록을 보여 주므로, `review.json`을 고쳐 다시 돌린다. 문제가 없으면 추가·중복 건너뜀 목록이 나온다. 훑어보고 이상한 행이 없으면 `--dry-run`을 빼고 실행한다.

`append.mjs`가 알아서 하는 것: 처음 실행 때 맨 끝에 `출처URL` 열을 만든다(기존 20개 열의 순서는 그대로라 `promo/capture.mjs`처럼 열 번호로 읽는 코드에 영향이 없다), 보드라이프 주소와 이름으로 중복을 한 번 더 걸러 낸다(출처URL만 같은 것은 묶음에서 나온 다른 게임일 수 있어 중복으로 보지 않는다), `가격검색URL`(네이버 쇼핑)을 채운다, BOM·CRLF·따옴표를 기존 파일과 같게 쓴다.

dry-run의 "건너뜀" 목록에 넣으려던 게임이 있으면 이름이 CSV나 다른 초안과 겹친 것이니 이름을 확인한다.

## 5. 보고

사용자에게 짧게 알린다:
- 사이트별로 몇 개를 보고 몇 개를 넣었는지(예: "보드라이프 3, 텀블벅 41, 머미나우 27 → 71행 추가, 279 → 350행")
- 넣은 게임 이름 몇 개 예시와, 뺀 이유의 큰 묶음(관계없는 게임 N, 재펀딩 N, 굿즈·책 N)
- 보류한 후보(이름 + 주소 + 왜 애매한지)
- `git diff --stat murder_mystery_games.csv`. `출처URL` 열이 처음 생기는 실행에서는 모든 기존 행 끝에 쉼표가 붙어 전부 바뀐 것으로 나온다고 함께 알린다(값은 그대로).

커밋은 사용자가 원할 때만 하고, 할 때는 `git add murder_mystery_games.csv`로 이 파일만 올린다(저장소 루트의 mp4가 섞이지 않게). 사이트 게임 데이터(Firestore)에는 아무것도 쓰지 않는다. 이 CSV는 사이트와 따로 관리되는 자료다.

## 사이트 구조가 바뀌었을 때

스크립트가 0개를 찾거나 값이 비어 나오면 사이트 구조가 바뀐 것이다. 사이트별 읽기 코드는 모두 `scripts/sources.mjs`에 모여 있다.
- 보드라이프: 검색 `https://boardlife.co.kr/search.php?query=<검색어>&page=game`(서버에서 그림), 상세 `/game/<id>`의 `game-title-kr`, `game-info-label`, `data-bggweight`, `data-bgglang`, JSON-LD `aggregateRating`. 가격은 정적 HTML에 없어서 읽지 않는다.
- 텀블벅: 검색 API `https://tumblbug.com/api/v2/projects?query=<검색어>&page=<n>`, 선물 `https://tumblbug.com/api/v3/project/<uuid>/rewards?type=REGULAR`, 소개 `https://tumblbug.com/api/v2/project/<uuid>/story`. 페이지 자체는 JS로 그려서 HTML에는 내용이 없다.
- 머미나우: 고도몰 쇼핑몰. 목록 `https://murmynow.com/goods/goods_list.php?cateCd=001003&page=<n>`, 상세 `goods_view.php?goodsNo=<n>`.

구조를 새로 알아내야 하면 브라우저 패널로 페이지를 열고 네트워크 요청을 보면 빠르다. 고친 뒤에는 기존 CSV 행 몇 개를 다시 읽어 값이 같은지 확인한다(보드라이프는 `boardlifeDetail(id)` 결과를 그 게임의 CSV 행과 비교).
